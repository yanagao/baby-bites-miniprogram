版本 1.2.0。原生微信小程序，采用 JavaScript、WXML、WXSS 和腾讯 **TDesign MiniProgram 1.17.0**。正式 AppID：`wxc6c61fbebebe3340`；云环境：`cloud1-5gxmasdl05652531`。交付文件包含按需生成的 `miniprogram_npm/tdesign-miniprogram/`，首次导入无需安装 npm 依赖或重新构建。

## 打开与试用

1. 在微信开发者工具中登录有该 AppID 开发权限的微信。
2. 导入本文件夹 `baby-bites-miniprogram`，确认正式 AppID。使用现有云开发环境 `cloud1-5gxmasdl05652531`；无需新建环境或开通额外付费服务。
3. 点击「编译」检查模拟器；需要真机试用时，点击「预览」生成二维码，使用有权限的微信扫码。
4. 游客模式及旧测试号不能验收账号同步。工具若将 AppID 改为 `touristappid`，登录后需改回上面的正式 AppID 再预览。

项目已包含 `app.json` 和 `project.config.json`，不要导入网页版的 `dist` 目录。云函数调用无需另配业务服务器域名；公开照片的 HTTPS 下载仍需按真机提示核对存储域名的 `downloadFile` 合法域名。当前配置基础库为 3.7.12。

## 已实现

- **首页**：顶部标题仅为“小口袋”，动态问候与搜索放在天空蓝、薄荷绿的食材插画背景中；两张纵向大卡片展示“随机选餐 / 开始抽选”和“按食材找菜 / 去找菜”。随机入口使用用户提供的问号碗，按食材找菜入口使用用户提供的眨眼口袋 Logo；下方食材小图标保持原资源。食材预览优先展示当前临时选择；未选时仅展示示意食材，不视为用户已有。“最近常做”按当前账号近 30 个日历日的真实用餐记录统计，按次数、最近用餐日期及记录创建时间排序，排除未来、过期和已删除菜谱的记录；无近期记录时显示“今日推荐”。心形可直接收藏，事件携带渲染时账号标识，旧账号卡片事件不会修改新账号同 ID 菜谱。搜索、更多、详情和空态添加入口保持可用。
- **随机选餐**：天空蓝插画顶部使用问号碗与提示气泡，白色弧顶面板展示月龄、七种真实菜谱分类的多选偏好和“跳过不太喜欢的菜”开关。首次进入会读取当前账号已保存的宝宝生日，按中国日期计算已满月数，自动选中 6–8 个月、9–11 个月、12–17 个月或 18 个月以上；未设置有效生日、未满 6 个月或暂时无法读取时保持不限月龄。手动调整、多选或清除优先于迟到的生日响应，从详情返回不会重新覆盖选择；新打开随机页时重新读取生日。多个所选月龄取并集，再与分类、最近用餐喜好筛选取交集。月龄或分类未选即不限；旧单分类接口保持兼容。候选计数与抽取使用同一菜谱池；“换一个”避开当前结果，“看看做法”进入真实详情，返回后保持当前菜谱。收藏入口位于菜品图右上角，不触发详情跳转、不新增用餐记录。保留空态、单候选、旧反馈及账号切换保护，不编造营养标签或推荐数量。
- **菜谱适用月龄**：添加/编辑菜谱可多选适用月龄，保存后才生效；不选表示适用于所有月龄。旧菜谱缺少该字段或明确清空为 `[]` 时，也会参与任意月龄的随机抽选，结果显示「不限月龄」。设置具体月龄后，按所选范围匹配；分类和最近用餐喜好筛选继续叠加。不改写已有菜谱，也不批量补入月龄标签。可选字段 `ageGroups` 随私人云同步、备份、主动公开与保存副本保留，缺失字段保持缺失，显式 `[]` 用于清空。公开版本仍须主动更新，不随私人编辑自动改变。
- **食材与匹配结果**：插画顶部、搜索、“我家现有食材”计数及清空入口；默认八格为南瓜、鸡蛋、西兰花、小米、土豆、豆腐、胡萝卜、番茄，更多食材和自定义入口保留，现有食材图标不变。搜索或折叠保留隐藏选择；选中、取消或移除后下方立即显示匹配总数、齐全/待补计数及前四条横向菜谱预览，每条显示真实缺料情况。点击行进入做法，详情返回保留选材；“查看全部/查看菜谱”进入完整结果页，推荐无需先跳转才能看到。清空同步清空结果，无匹配时显示真实空态。

- **菜谱分类**：早餐饼、肉饼肉丸、面包糕点、粥饭主食、蔬菜手抓、蒸蛋豆腐、汤羹炖菜。随机选餐、列表和编辑表单共用同一套分类。旧版三类菜谱及备份在读取时兼容归类，保留原菜谱、收藏、照片和用餐记录，不因升级主动覆写本机数据；口感字段保持不变。
- **详情**：私人和公开菜谱均以顶部大图开场，再展示标题、真实标签、食材与用量和做法。私人详情保留备注、上次反馈、收藏、记一餐、编辑及带确认的删除；公开详情可保存独立副本，不能编辑原作者内容。顶部大图布局已实现，当前实际点击补测状态见「验证状态」。

- **记录用餐**：按日期、菜谱小卡、三档喜好横排、食量标签、备注和底部固定保存排列。喜好仍为“不太喜欢 / 还不错 / 很喜欢”，食量沿用已有含义及历史值，不从参考图填造月龄或分数食量；操作在明确保存前不持久化。

- **发现**：从真实公开食谱中查看最新分享，支持按菜名、食材或作者搜索、继续加载，以及只看关注作者的公开菜谱。没有内容、无搜索结果和请求失败分别显示真实状态，不展示虚构的用户或菜谱。

## 数据与备份

同一微信账号在同一正式 AppID、同一云环境下，可以同步宝宝称呼、菜谱、照片、收藏及用餐记录。不同微信账号分别保存；不同 AppID、其他云环境及网页版不会自动合并，需要由用户导入备份迁移。同步不需要读取微信昵称、头像或手机号。

修改先保存到本机，再自动同步；进入前台、联网恢复和后续修改会触发同步，也可在「设置 → 微信账号同步」点击「立即同步」。状态分别显示未启用、等待同步、正在同步、已同步或未完成。换设备前确认已显示「已同步」，照片下载、备份导出及首次恢复仍需网络。

旧版本数据键 `baby-bites-v1` 继续保留。首次成功识别微信账号时，将未绑定的旧数据合并到该账号缓存，并记录迁移归属，防止再次合并给另一个账号。账号缓存使用 `baby-bites-account-<owner>`，当前缓存标识使用 `baby-bites-active-owner`；`owner` 是服务端从微信可信身份计算出的哈希，不由客户端自报。没有网络时保留最后一次确认账号的本机修改，未能确认的新账号不会上传旧账号数据。切换 AppID 后旧照片路径可能失效，迁移前须先导出含照片的备份。

多设备同步按条目 ID 合并，较新的 `updatedAt` 优先；同一条目的同时编辑不会逐字段拼接。明确导入本机已知删除的条目会作为恢复操作保留；相同版本的备份可修复已失效的本机照片，不替换有效照片或较新内容。删除会保留删除记录，避免另一设备的旧缓存把已删内容恢复；删除菜谱后，其对应的用餐记录也不会重新出现。云端以版本号事务提交，有冲突时先读取新版本、重新合并再提交，不直接覆盖其他设备的新内容。同步期间继续编辑的本机变化保留在下一次同步队列里。

菜谱更新、用餐记录新增及编辑都先校验后提交；存储失败时不更新内存。读取到损坏内容时保留原存储，普通编辑会被阻止，需导入有效备份恢复。记录编辑保留 `id` 和 `createdAt`，增加可选 `updatedAt`；旧备份缺失该字段时按 0 处理，合并时保留同一条记录较新的修改。

未同步照片使用微信持久文件路径；同步成功后使用属于当前账号的云端照片。导出时将本机或云端照片转换为嵌入图片的 JSON，导入时重新保存到当前设备。单张照片最多 2 MB，备份文件最多 20 MB，云端数据快照最多 5 MiB（照片独立存储，不嵌入快照）。

导出分两步：先生成备份文件，再点击「分享备份文件」（手机）或「保存到电脑」（桌面微信）。文件分享必须由新的点击直接触发，不能在照片异步读写完成后自动调用。取消、失败或离开待确认页面会清理临时备份；正在分享的文件等系统回调后再清理。导出不修改原有菜谱、照片和用餐记录。

## 交互依据

交互继续参考 [Apple HIG](https://developer.apple.com/design/human-interface-guidelines)，通过小程序和 TDesign 的公开能力实现，不复制 iOS 系统控件外观。

- [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars)：四个 Tab 稳定对应「首页 / 发现 / 记录 / 我的」，中央添加是独立操作，选中状态来自真实路由。
- [Writing](https://developer.apple.com/design/human-interface-guidelines/writing) 与 [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：操作写明结果；家长收藏、宝宝喜好、新增用餐和编辑历史分别表达。
- [Entering data](https://developer.apple.com/design/human-interface-guidelines/entering-data) 与 [Pickers](https://developer.apple.com/design/human-interface-guidelines/pickers)：普通新增默认今天，从记录日历新增沿用选中日期；喜好不预选，食量选填，错误贴近字段。
- [Feedback](https://developer.apple.com/design/human-interface-guidelines/feedback)：选中食材同时有勾与底色，并提供可移除标签；收藏使用图标和文字；保存失败保留输入，防止重复提交。
- [Alerts](https://developer.apple.com/design/human-interface-guidelines/alerts) 与 [Modality](https://developer.apple.com/design/human-interface-guidelines/modality)：丢弃修改、删除和合并导入需要确认，删除菜谱说明关联记录数量。
- [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：导航保留文字，反馈不只依赖颜色，图标按钮提供中文名称；字号及读屏效果仍需真机检查。

## 字体、图标与运行边界

TDesign 图标使用官方 0.4.5 字体原始字节，Base64 数据保存在 `recipe-media/fonts/tdesign-icons-0.4.5.js`。启动时通过 `require.async` 获取资源分包中的字体，再调用 `wx.loadFontFace`；分包缓存后可离线加载。微信 API 定义从基础库 3.7.9 开始支持 Data URL；低版本、分包不可用或本地字体加载失败时回退官方 HTTPS 字体。每阶段最多等待 10 秒，并发请求合并、成功缓存，失败后可重试；字体准备不阻塞页面操作。原始图标字形和字体字节未修改，颜色与尺寸通过公开 API 设置。依据见 [微信官方 API 类型定义](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.api.d.ts) 和 `assets/fonts/NOTICE.txt`。

当前标题、正文及兼容保留的 `.brush` 类均采用系统无衬线字体。历史 PocketBrush 字体源码已移到工作区 `output/cute-assets-original/pocket-brush.js` 存档，不再加载或打包；字符、来源与重建说明见 `assets/fonts/README.md`。口袋 Logo 与全部食材插画保持原画面；食材图集仅重新压缩 PNG 数据流，像素、尺寸、透明度和颜色元信息均不变，记录见 `assets/cute/ASSETS.md`。

顶部使用 TDesign Navbar 和官方 `placeholder` 处理状态栏与微信胶囊；底部 TDesign TabBar 在四个 Tab 页正文末尾渲染，其 `placeholder` 参与页面布局。原生自定义导航宿主仅保留空壳，避免重复导航和占位失效。

未保存提醒仅在实际修改后启用。两个编辑页的返回及取消按钮使用放弃确认逻辑，微信 `enableAlertBeforeUnload` 作为系统返回的补充。微信文档不保证拦截侧滑返回，因此不声称所有退出方式都能恢复草稿。

- `pages/`：首页、发现、记录、我的四个 Tab，以及食谱、按食材找菜（页内即时推荐）、兼容保留的食材结果、详情、菜谱编辑、记录编辑、随机选餐、设置、主页、关注与粉丝、公开食谱，共 15 个业务页。
- `pages/profile/page.js` 与 `pages/profile/content.wxml`：本人 Tab 主页与独立分享主页共用的状态/交互与页面内容；本人收藏和记录不会暴露给访客。
- `components/`：菜谱图片卡片、食材插画、底部导航等业务组件。
- `custom-tab-bar/`：空导航宿主，实际导航在四个 Tab 页内。
- `app.wxss`：本项目主题变量、正文与标题、通用布局样式。
- `miniprogram_npm/tdesign-miniprogram/`：随交付附带的按需组件产物，必须保留。
- `scripts/build-tdesign.cjs`：组件构建与依赖解析；`scripts/validate.py`：静态和原生编译检查；`scripts/check-package.cjs`：打包配置和资源体积预检。
- `utils/store.js`：校验和原子存储；`selectors.js`：筛选、匹配、图片与随机；`recipe-covers.js`：准确默认配图映射；`cover-loader.js`：云端静态配图加载、内容校验、本地缓存、超时与重试；`calendar.js`：日期与周统计；`backup.js`：含照片备份。
- `utils/social.js`：公开主页、发现、关注、公开食谱与分享码接口；`utils/profile-poster.js`：主页海报绘制与临时文件清理。
- `utils/cloud-sync.js`：云端同步调度及照片迁移；`utils/sync-merge.js`：合并与删除记录；`config/cloud.js`：云环境启用配置。
- `cloudfunctions/babyBitesSync/`：身份与版本提交云函数；`cloudfunctions/babyBitesSocial/`：公开主页、发现、关注、公开食谱与分享码云函数；`cloud/`：权限规则模板。共享环境必须按已有用途审查后应用模板。
- `data/recipes.js`：21 道示例菜谱，包含食材用量、步骤和口感说明。
- `assets/cute/`：口袋角色与食材插画；`assets/food/ASSETS.md`：默认配图来源和映射说明。
- `data/recipe-cover-catalog.js`：21 张静态配图的公开元信息；`cloudfunctions/babyBitesAssets/manifest.json`：部署用固定云存储文件清单。配图 JPEG 原文件归档在小程序目录外的工作区 `../output/cloud-recipe-covers/source/`，不打包。
- `recipe-media/fonts/`：TDesign 官方图标字体和许可证；分包声明页不增加业务入口。
- `assets/fonts/`：字体来源、许可证和旧设计字体的存档说明。
- `tests/`：回归测试，不打入小程序包。
